Most real apps show data that lives on a server: posts, products, users. In the JavaScript module you used `fetch` with `async`/`await`. In the last lesson you learned that effects are how React syncs with the outside world. Fetching data is exactly that kind of sync, so this lesson combines the two.

## Three states: loading, error, data

A request takes time and can fail, so the screen has three possible situations. We keep a piece of state for each:

```jsx-live
import { useState, useEffect } from "react";

export default function App() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function load() {
      try {
        const response = await fetch("https://jsonplaceholder.typicode.com/users");
        if (!response.ok) {
          throw new Error(`Request failed: ${response.status}`);
        }
        const data = await response.json();
        setUsers(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }
    load();
  }, []);

  if (loading) return <p style={{ padding: 16 }}>Loading...</p>;
  if (error) return <p style={{ padding: 16, color: "crimson" }}>Error: {error}</p>;

  return (
    <ul style={{ fontFamily: "sans-serif" }}>
      {users.map((user) => (
        <li key={user.id}>
          {user.name} ({user.email})
        </li>
      ))}
      {/* Try misspelling "users" in the URL to see the error state. */}
    </ul>
  );
}
```

Walking through it:

- The effect has `[]` as its dependency array, so it fetches once, after the first render.
- The effect function itself cannot be `async`, so we define an `async function load()` inside it and call it.
- `fetch` only throws for network failures. A 404 or 500 still "succeeds," so we check `response.ok` and throw ourselves.
- `finally` turns off loading whether the request worked or not.
- Early `return`s show the loading and error screens; otherwise we render the list with `user.id` as the key.

## Refetching when something changes

Often what you fetch depends on a prop or state, like which user is selected. Put that value in the dependency array and the effect runs again whenever it changes.

There is a catch. If you click quickly, two requests are in flight, and the **older** one might finish last and overwrite the newer data. The fix is a flag in the effect plus a cleanup function:

```jsx-live
import { useState, useEffect } from "react";

function UserCard({ userId }) {
  const [user, setUser] = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    let ignore = false;
    setUser(null);
    setError(null);

    async function load() {
      try {
        const response = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`);
        if (!response.ok) throw new Error(`Request failed: ${response.status}`);
        const data = await response.json();
        if (!ignore) setUser(data);
      } catch (err) {
        if (!ignore) setError(err.message);
      }
    }
    load();

    return () => {
      ignore = true;
    };
  }, [userId]);

  if (error) return <p style={{ color: "crimson" }}>Error: {error}</p>;
  if (!user) return <p>Loading user {userId}...</p>;
  return (
    <div>
      <h3>{user.name}</h3>
      <p>Company: {user.company.name}</p>
      <p>City: {user.address.city}</p>
    </div>
  );
}

export default function App() {
  const [userId, setUserId] = useState(1);
  return (
    <div style={{ fontFamily: "sans-serif", padding: 16 }}>
      <button onClick={() => setUserId(userId > 1 ? userId - 1 : 1)}>Previous</button>{" "}
      <button onClick={() => setUserId(userId < 10 ? userId + 1 : 10)}>Next</button>
      <UserCard userId={userId} />
      {/* Try setting userId to 99 to see the error message. */}
    </div>
  );
}
```

Each time `userId` changes, React runs the old effect's cleanup first, which sets that run's `ignore` to `true`. So when the old request eventually finishes, it sees `ignore` and quietly does nothing. Only the newest request is allowed to update state.

<Note>
Every run of the effect gets its **own** `ignore` variable, because `let ignore = false` runs fresh each time. The cleanup flips only the one that belongs to the old run. That is why this works even with many requests in flight.
</Note>

## In real projects

Writing this by hand teaches you what is happening, but it gets repetitive. Larger apps usually use a framework feature (like Next.js server components) or a library such as TanStack Query, which handle loading, errors, caching, and stale responses for you. The ideas are the same ones you just used.

## Recap

- Fetch inside `useEffect`, using an inner `async` function.
- Track loading, error, and data in state, and render a different view for each.
- Check `response.ok`, because `fetch` does not throw on HTTP errors.
- Put the values you fetch by in the dependency array to refetch when they change.
- Use a `let ignore = false` flag and a cleanup to ignore stale responses.
